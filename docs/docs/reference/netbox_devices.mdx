---
title: NetBox Devices
---

Devices, modules, device roles, platforms, virtual chassis, virtual device contexts, device types, module types, manufacturers, device components, inventory items and MAC addresses: the Devices section of the NetBox navigation menu, mapped from the NetBox 4.7 dcim tables. NetBox device type component templates map to Infrahub object templates of devices.

## Details

- **Dependencies:**
    - [netbox/netbox_organization](netbox_organization)

## Use cases

This extension covers:
- Import NetBox devices with their device types, interfaces, ports, bays, modules and inventory items, and the NetBox statuses and choices.
- Define a device template with its interfaces and ports, and create devices from it, in place of NetBox device type component templates.
- Generate device configurations as Infrahub artifacts: devices inherit CoreArtifactTarget.

Out of scope, and what to reach for instead:
- Module type component templates. Infrahub generates templates for devices and their components only, so create module components on the device.
- The counters and cached columns that NetBox computes.
- Half rack units, such as a 0.5U device height. Heights are whole rack units.
- Decimal weights, diameters and flow rates. They are stored as whole numbers in grams, millimeters and liters per minute, because Infrahub has no decimal attribute kind.
- Devices without a name, or with a name that another device uses. Device names are mandatory and unique in Infrahub, so that devices, their components and their virtual device contexts have human-friendly IDs.
- Devices without a platform or a tenant. Infrahub requires both on every device.
- Unique names for module bays and inventory items. NetBox makes them unique within an optional parent, which an Infrahub uniqueness constraint cannot include.
- Device roles, platforms and module bay types with the same name under different parents or manufacturers. Their names are unique in Infrahub, so that other objects can refer to them by name.
- Clusters (virtualization), wireless LANs (wireless), and config templates (extras).
