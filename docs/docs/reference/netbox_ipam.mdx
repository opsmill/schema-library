---
title: NetBox IPAM
---

VRFs, route targets, RIRs, aggregates, prefixes, IP ranges, IP addresses, VLAN groups, VLANs, VLAN translation policies, ASNs, FHRP groups and services, mapped from the NetBox 4.7 ipam tables. Each VRF is an Infrahub IP namespace, so Infrahub arranges the prefixes and IP addresses of each VRF in a separate hierarchy.

## Details

- **Dependencies:**
    - [netbox/netbox_organization](netbox_organization)
    - [netbox/netbox_devices](netbox_devices)

## Use cases

This extension covers:
- Import NetBox IP address management data, including the same prefix in several VRFs.
- Assign IP addresses to device interfaces, set the primary IP addresses of devices, and assign VLANs and a VRF to interfaces.

Out of scope, and what to reach for instead:
- Uniqueness of prefixes and IP addresses. NetBox checks it in application logic, depending on the VRF setting and the address role. This schema does not enforce it.
- Unique VLAN and VLAN group names and VLAN IDs. NetBox makes them unique within an optional VLAN group or scope, which an Infrahub uniqueness constraint cannot include.
- VM interfaces and clusters (virtualization) as targets of IP addresses, FHRP groups, services and VLAN groups.
